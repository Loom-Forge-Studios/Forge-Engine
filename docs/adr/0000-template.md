# ADR NNNN — Title in the imperative ("Use X for Y")

- **Status:** proposed | accepted | superseded by ADR NNNN
- **Date:** YYYY-MM-DD
- **Plan references:** chapters, invariants (I-n), DoD ids (Mn-n), decisions (E-n / O-n / D-n)

ADRs are numbered by allocation: take the next free number, never renumber. A decision
that changes a golden hash, a frozen contract (M0-20) or an invariant is a plan amendment
and says so here.

## Context

What forces the decision. What the plan says and where it leaves the choice open.

## Decision

The choice, stated so someone can check the code against it.

## Why — the owner's two rules

1. **Better for the user**, not merely easier to code: …
2. **Faster / more efficient engine**: …

## Alternatives rejected

Each with the reason it lost.

## Consequences

What this makes easy, what it makes hard, what must now be true (and which test or gate
row checks it).
