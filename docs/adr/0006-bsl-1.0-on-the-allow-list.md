# ADR 0006 — Admit BSL-1.0 to the permissive allow-list and back the clipboard with arboard

- **Status:** accepted
- **Date:** 2026-09-20
- **Plan references:** Appendix A.5; I13; Ch.21 §21.2, §21.9; orchestrator decision D-8;
  ADR 0012 §2; gate row `C-ui-os-clipboard`; WP-U2

## Context

ADR 0012 left the OS clipboard `UNBUILT` because `arboard`'s Windows backend
(`clipboard-win`, `error-code`) is licensed under the Boost Software License 1.0, which was
not on the Appendix A.5 allow-list, and widening that list is an owner decision. The owner
has now decided (D-8): BSL-1.0 is permissive, has no copyleft of any strength, and — unlike
MIT or Apache-2.0 — does not even require the notice to be reproduced in binary
distributions.

## Decision

1. **BSL-1.0 joins the permissive list** in all three places that must agree:
   `deny.toml` (`cargo-deny`), `about.toml` (`cargo-about`, NOTICES) and
   `xtask/src/licence_audit.rs::PERMISSIVE` (which audits the other two, so the list still
   cannot be widened to admit copyleft by editing a config file). Appendix A.5 records it.
2. **`OsClipboard`** (feature `os-clipboard`, default, implied by `winit`) implements the
   `Clipboard` trait over `arboard`, with default features off (no image support is pulled
   in). The winit runner installs it for every window.
   * Text goes to and comes from the OS clipboard.
   * Structured content (`FORGE_RON_MIME`) is kept beside the text it was copied with and
     returned only while the OS clipboard still holds that text, so another application's
     copy replaces both — a paste never returns a stale structured payload with someone
     else's text.
   * If the platform clipboard cannot be opened (no display server), it serves the D-4
     in-process clipboard and `backend_name()` says so. If one write is refused (the
     clipboard is briefly locked by another process), that copy is kept in-process.
3. **The guard** is `crates/forge-ui/tests/test_ui_os_clipboard.rs`: an independent
   `arboard` handle — what every other application sees — must read Forge's copy, and a
   paste in Forge must read the other application's copy. The positive control runs the
   same check against `InProcessClipboard` and must fail. The user's clipboard text is
   saved and restored. Without a platform clipboard the test prints
   `AWAITING(no OS clipboard)`. Gate row `C-ui-os-clipboard` is `Bound`.

## Why — the owner's two rules

1. **Better for the user:** copy and paste between Forge and every other application work,
   which is what a user expects of a text field.
2. **Faster engine:** `arboard` is a direct platform call (Win32 / X11 / Wayland), no
   child process per paste (the rejected ADR 0012 alternative cost hundreds of ms).

## Alternatives rejected

- **Keeping the in-process clipboard:** honest but a daily annoyance; the owner cleared the
  licence.
- **Writing the Win32 clipboard code in `forge-ui`:** needs `unsafe` in a
  `#![forbid(unsafe_code)]` crate (Ch.1.5).

## Consequences

- NOTICES now lists BSL-1.0 and the crates under it.
- M2-21's remaining gap is RON-over-reflect, which needs `forge-reflect` (WP-04).
