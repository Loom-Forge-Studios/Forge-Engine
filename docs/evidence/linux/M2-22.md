# M2-22 — accessibility on Linux: the AT-SPI tree observed

Image `forge-linux-verify:1.98.1` (`sha256:0129932d13abccd08261a95d360084b6d36111e44e3b52e8bf401fb84baac7e7`), rebuilt
from the same pinned `rust:1.98.1-bookworm@sha256:93ce27a88655056a51dbdd8f5f2d7ddc071c7b0070fb288a37b5a285fc83971e` with one new layer:
`at-spi2-core` 2.46.0-5 and `dbus` 1.14.10-1~deb12u1 (WP-U12; environment in [README](README.md)); 2026-09-24.

Command (Windows host):

```
just verify-linux bash tools/docker/linux-verify/atspi-probe.sh
```

verify-linux: snapshot tree c98427bb0a76dd3a22f7e4e14b3b35ce76678798 of <lane B worktree>

What it does, as a screen reader would, with nothing of forge-ui linked into the client:
a private D-Bus session (`dbus-run-session`), the accessibility bus and registry
(`/usr/libexec/at-spi-bus-launcher --launch-immediately`), accessibility switched on for the
session (`org.a11y.Status.IsEnabled = true`, `atspi_probe enable`), then `ui_gallery` under
Xvfb, then `atspi_probe walk`: find the
application on the registry, walk its tree over the bus (`GetChildren`, `GetRole`, the
`Name` property), and check the widgets it expects by AT-SPI role and name.

## Observed

- AccessKit's Linux adapter (`accesskit_winit` → `accesskit_unix` → zbus) activated lazily
  when accessibility was switched on and registered `ui_gallery` within 0.3 s.
- 113 nodes, 108 named: frame, panels, push buttons, check box, slider, radio buttons, page
  tab lists and tabs, scroll panes, images (the 53 icons, named), paragraph with a link,
  status bar, separator, scroll bar.
- Every expectation found: push button Save, Cancel, Close; check box Snap to grid; slider
  Opacity; radio button World; page tab Jobs.
- **Defect found and fixed:** the first walk showed the radio group `Gizmo space` with no
  children — its options were not exposed. `RadioGroup` now exposes each option as a
  virtual radio button (state, position in set, Click); the walk above shows Local, World,
  Frame, and `test_ui_a11y_tree` guards it on every leg.
- The software Vulkan device was lavapipe:

```

linux-verify: vulkan 	deviceName         = llvmpipe (LLVM 15.0.6, 256 bits)
linux-verify: vulkan 	driverName         = llvmpipe
```
