# L-11: turn_for_control positive control

## What was done

### timed.rs changes (crates/forge-trace/src/timed.rs)

- `ControlTurn` struct — tracks the thread in `by_thread` (so `machine_lock` refuses
  this thread for self-deadlock protection) but acquires **no** shared file lock on
  `LOCK_FILE`.
- `turn_for_control() -> ControlTurn` — panics if called while real `gpu_turn` handles
  are still live (asserts `held == 0 && shared.is_none()`), ensuring the caller resets
  the state before injecting the fault.
- `holds_turn_for_control() -> bool` — returns whether this process holds a control
  turn.
- `impl Drop for ControlTurn` — reverses `by_thread` tracking (does not touch `held`)
  so the `TURNS` state is clean after the control turn drops.

### Test (crates/forge-trace/tests/test_turn_for_control.rs)

- `positive_control_without_a_real_lock_timed_body_grants` — the W2 positive control:
  after dropping all real GPU turns, a control turn is taken, then a timed body on
  another thread takes the exclusive timed lock successfully. This proves the real
  shared lock acquisition in `gpu_turn()` is what blocks `machine_lock` in the original
  exclusion test `a_gpu_turn_holds_the_lock_shared`.

### W2 proof: removing `lock_shared` fails the existing test

I temporarily commented out `lock_shared()` in `gpu_turn()` and confirmed that the
existing test `a_gpu_turn_holds_the_lock_shared` fails:

```
thread 'a_gpu_turn_holds_the_lock_shared' panicked at ...
the lock was free for exclusive use while a GPU turn was held
```

This proves the existing test exercises the lock, not a lock that is always exclusive.
